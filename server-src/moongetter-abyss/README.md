# Abyss

`moongetter-abyss` resolves public Abyss embeds without a WebView. The factory name is **Abyss**. It is registered in the regular server bundle, and the sample's initial URL is:

[Sample embed](https://argtesa.top/?v=vu9jynYrzV)

The factory recognizes HTTPS links on `abyss.to` and its subdomains, plus `argtesa.top` and its subdomains, using either `?v=<slug>` or a supported slug path. It rejects unrelated hosts, malformed identifiers, and generated Google Storage placeholder URLs. Add newly verified mirror domains explicitly to `AbyssPayload.PATTERN`; matching every host with `?v=` would collide with other providers.

## Workflow

1. Fetch the embed using the injected HTTP client and validate the metadata slug against the requested identifier.
2. Decode `JSON.parse(atob(datas))` with the browser's Latin-1 byte semantics.
3. Decrypt the media metadata using the provider's MD5-derived AES-CTR format.
4. Validate the split MP4 origins, paths, sizes, and part sizes; select H.264 sources.
5. Open a loopback range proxy, decrypt the first 64 KiB, and map requested byte ranges onto the actual file parts.
6. Validate the listener, HTTP range behavior, and decrypted MP4 signature before returning playback requests.

The Google Storage-looking URLs generated by this player are service-worker placeholders. They are not ordinary Google Cloud Storage objects and must not be returned as playable media. The native `/sora/` route tested for this sample returned 404. The validated implementation uses the split-file route instead.

The sample uses **OkHttp on Android/JVM** and Darwin on iOS. The supplied embed rejected the CIO TLS handshake with a protocol-version alert. Use a platform TLS engine for this provider; certificate validation remains enabled.

## Lifecycle

Returned URLs point to `http://127.0.0.1:<ephemeral-port>/<random-session>/video.mp4`. The operating system assigns the port, so an occupied fixed port does not conflict. The listener binds only to loopback. Sessions are limited to four, requests are bounded, upstream content ranges are checked, and idle sessions expire after ten minutes without requests. The proxy stores a decrypted 64 KiB prefix per source and reads subsequent data in blocks of at most 256 KiB; it does not download the complete file during extraction.

Release every returned local URL when its playlist is no longer needed:

```kotlin
import com.ead.lib.moongetter.abyss.AbyssProxy

suspend fun releasePlaylist(urls: List<String>) {
    urls.forEach { AbyssProxy.release(it) }
}

suspend fun stopAbyssPlayback() {
    AbyssProxy.closeAll()
}
```

The sample retains sessions while switching qualities, releases the previous playlist before another extraction, and releases URLs when its ViewModel clears. Apps using the module directly must manage the same lifecycle. URLs are device-local and cannot be shared with another device.

## Validation on October 10, 2026

The supplied embed returned three H.264 qualities: 480p, 720p, and 1080p. Live extraction and startup validation took **2.363 seconds**. Checks passed for HTTP 206 ranges at the beginning, across the encrypted-prefix boundary, and across the 512 MiB file-part boundary. FFmpeg decoded three seconds at the beginning and after seeking to 600 seconds, both with exit code 0.

Six offline regression tests passed on JVM and iOS simulator: provider matching and placeholder rejection, Latin-1 metadata decoding/decryption, range parsing, validated origin matching, prefix/part reconstruction, and incorrect upstream range rejection. The Android sample, desktop classes, and shared iPhone code compile with the provider included. The regular server bundle and sample-client live test also passed: first source resolution 2.088 s, repeated resolution 1.646 s; local MP4 access returned HTTP 206 in 4.84 ms and 2.29 ms. Each iteration released all playlist sessions before the next extraction. These initial checks did not test physical-device playback. After the HEAD response fix below, the user confirmed the updated sample works on a physical iPhone on 2026-10-10. Android player playback remains unverified for this provider.

```shell
./gradlew :moongetter-abyss:jvmTest :moongetter-abyss:iosSimulatorArm64Test
MOONGETTER_ABYSS_TEST_URL='https://argtesa.top/?v=vu9jynYrzV' MOONGETTER_ABYSS_FFMPEG=1 ./gradlew :moongetter-abyss:jvmTest --tests com.ead.lib.moongetter.abyss.AbyssLiveTest
```

Live tests are opt-in; an unconfigured live test does not establish availability. This release implementation supports the observed encrypted metadata and split H.264 MP4 format. AV1, other undocumented formats, and unknown mirror/CDN domains are not assumed supported. Host availability and URLs may change.

### iOS response validation

The loopback regression test uses the platform HTTP client (Darwin on iOS),
checks that HEAD and ranged GET responses contain a single Content-Length,
and validates decrypted MP4 bytes. HEAD responses use Ktor NoContent with
explicit content metadata; adding entity headers to respond(status) produces
duplicate headers that iOS rejects with NSURLErrorDomain -1017. MEGA uses
the same corrected response handling.

The real-source native diagnostic remains opt-in. The 2026-10-10 simulator
run reached a certificate trust error (-1202) at argtesa.top, before extraction.
The supplied physical-iPhone log instead shows embed HTTP 200 followed by
the duplicate loopback-header failure. Certificate validation remains enabled;
simulator results do not establish physical-device playback.

After installing the corrected signed iPhone sample, the user confirmed it works. This device result is separate from the simulator certificate failure.
